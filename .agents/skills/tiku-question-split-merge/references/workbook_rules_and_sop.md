## 二、何时拆分 vs 何时合并（判定标准）

### 2.1 不拆分的场景（必须保持或合并为单题）
1. **《老姚高数》中的并列计算/判别小问**：
   - 原书中同一个题号下给出多个并列极限、导数、积分或级数判别式（如「判别下列级数的敛散性：(1)... (2)... (3)... (4)...」，曾被误拆为 `12.1-1~3`、`12.2-5~8`、`12.3-4~7` 等），**一律视为同一道大题，不进行小题拆分**。
   - 若历史题库中已将其拆开，须执行**多题合并**操作，恢复原书一题一码的结构。
2. **上下文强耦合的递进设问**：
   - 第 (2) 问直接依赖第 (1) 问的中间结论或物理模型，且原书解析合写在一起无法清晰剥离时，保持单题不拆。

### 2.2 拆分的场景（一题多问拆为独立子题）
1. **《822教材》课后习题的独立小问**：
   - 当一道大题包含多个独立系统图、独立传递函数求取或独立大段计算（如 `2-3 (1)`~`(3)`、`3-21 (1)`~`(2)`、`3-32 (1)`~`(2)`），且每个小问篇幅较大、熟练度需独立追踪时，按原书小问号拆分为独立题目。
2. **《李范全书》《基础30讲》《强化36讲》《1000题》中的独立综合小问**：
   - 如《1000题》中的基本计算大题（`9-1 (1)` ~ `9-1 (24)`）或《李范全书》中的多问例题（`例8-1 (I)`, `例8-1 (II)`），按既定颗粒度拆分为独立子题。

## 三、各科目与各题库差异化规范（Per-Workbook Rules）

不同题本在 `js/chapters.js` 中的数据结构与磁盘文件命名规则存在显著差异，操作前必须严格对号入座：

### 3.1 《老姚高数》（`wb: "老姚高数"`）—— 双轨映射与全章顺延机制

> [!CAUTION]
> 《老姚高数》采用 **`labels`（小节题号）+ `imgLabels`（全章连续图片号）** 双轨制！在章节中间合并或插入题目，会引发从变动点直到本章末尾的**全章顺延平移（Domino Shift）**。

1. **双轨字段含义**：
   - `labels`：前端 UI 显示的小节题号，格式为 `"{章}.{节}-{小节内序号}"`，如 `"12.2-5"`。每进入新的一节，小节内序号从 `1` 重新开始。
   - `imgLabels`：映射磁盘图片文件名与 JSON 存储键的**全章连续编号**，格式为 `"{章}-{全章流水号}"`，如 `"12-13"`（对应磁盘文件 `pb_12-13_question.png` / `pb_12-13_solution.png` 以及 JSON 键 `"pb_12-13"`）。
2. **小节与「补充练习」边界（`sections` 数组）**：
   - 每个章节包含 `sections` 数组，每项结构为：
     ```js
     { name: '12.2 正项级数及其审敛法', start: 9, count: 16, exampleCount: 11 }
     ```
   - **核心区分**：小节内前 `exampleCount` 道题为**正文例题**；后 `count - exampleCount` 道题在前端会被标记并渲染为**「补充练习」**（对应原书每节末尾的「补充练习」栏目）。
   - **严禁混淆**：重裁或核对时，必须对照原书 PDF 确认哪些题位于正文、哪些题位于「补充练习」标题之后，准确设置 `exampleCount`！
3. **拆合时的连锁更新要求（缺一不可）**：
   假设在第 $k$ 节合并了 $m$ 道题（总题数减少 $\Delta = m - 1$）：
   - **① 本节后续题号**：第 $k$ 节内变动点之后的 `labels` 序号全部减 $\Delta$；
   - **② 全章后续图片号**：从变动点起到本章最后一题的 `imgLabels` 流水号全部减 $\Delta$；
   - **③ 磁盘文件名**：`题库/老姚高数/chX/` 下从变动点起到本章末尾的所有 `pb_{ch}-{N}_question.png` 和 `pb_{ch}-{N}_solution.png` 文件名同步减 $\Delta$；
   - **④ `sections` 偏移**：第 $k$ 节的 `count`（及 `exampleCount`，视变动发生在例题区还是补充练习区而定）减 $\Delta$；第 $k+1$ 节至最后一节的 `start` 全部减 $\Delta$；章节 `total` 减 $\Delta$；
   - **⑤ 数据库键名**：`kaoyan_tiku_data.json` 中 `shu1_laoyao_chX.questions` 下对应的 `pb_{ch}-{N}` 键名同步减 $\Delta$；
   - **⑥ 语义清单**：检查 `题库/kaoyan-semantic-data/semantic_manifest.json` 是否包含该章节条目，若有则同步更新。

### 3.2 《李范全书》（`wb: "李范全书"`）与《李范习题》（`wb: "李范习题"`）

1. **命名与小问规范**：
   - 《李范全书》全部为正文例题，`labels` 格式为 `"例8-1"`，拆分小问采用罗马数字括号 `"例8-1 (I)"`, `"例8-1 (II)"`（对应磁盘文件名 `ex_8-1_(I)_question.png`）。

### 3.3 《基础30讲》（`wb: "基础30讲"`）与《强化36讲》（`wb: "强化36讲"`）

1. **例题 + 习题双段结构（`parts`）**：
   - 章节内前半段为正文例题（`"例9-3 (1)"` $\to$ `ex_9-3_(1)`），后半段为课后习题（`"9-1"` $\to$ `pb_9-1`），由 `parts: [{ name: '例题', start, count }, { name: '习题', start, count }]` 划分。
2. **三级微观知识树（`MATH_KNOWLEDGE_DATA`）强耦合**：
   - `MATH_KNOWLEDGE_DATA[chId]` 中定义了与 `labels` 0-based 索引严格对应的：
     - `sections`: 一级小节（含 `start`, `count`）
     - `subSections`: 二级微观题型/知识点（含 `id`, `name`, `start`, `count`）
     - `itemDescs`: 逐题一行考点简述数组（长度必须等于章节自身 `total`）
   - **铁律**：在这两套题本中拆分或合并任何题目时，**必须同步修改 `MATH_KNOWLEDGE_DATA[chId]` 中的 `sections`、`subSections` 的 `start`/`count` 以及 `itemDescs` 数组**！否则会导致前端微观知识抽屉错位。
3. **36讲伴章挂载**：
   - 《强化36讲》通过 `q1000Id` 自动挂载《1000题》对应章节，伴章题目的存储键带 `q1000::` 前缀。

### 3.6 822 控制工程基础（`822教材` / `小题300` / `强化240` / `真题分类`）

1. **《822教材》（`wb: "822教材"`）**：
   - **固定画布宽度**：所有题干与解析图片的像素宽度**严格恒等于 `2005 px`**。
   - **扫描件端正度（Deskew）**：原书与《习题解》均为扫描版 PDF，重裁时必须检查文字行是否水平，必要时进行微角度旋转校正并裁除扫描黑边。
   - **三分区固定顺序（`partOrder: ['习题', '例题', '章末例题']`）**：
     - 章节 `labels` 数组必须严格按以下三段顺序排列：
       1. **习题**：`"3-21 (1)"` $\to$ `pb_3-21_(1)_question.png`
       2. **例题**：`"例3-1"` $\to$ `ex_3-1_question.png`
       3. **章末例题**：`"例题1"` $\to$ `ce_1_question.png`
     - 若拆分了某道「习题」，不仅要更新 `parts[0]`（习题）的 `count`，**还必须将 `parts[1]`（例题）和 `parts[2]`（章末例题）的 `start` 同步后移**！
   - **第 9 章题号特例**：
     - `822_ch9`（第九章 计算机控制系统）在原教材与《习题解》中，**课后习题编号为 `10-1` ~ `10-23`**（对应 `pb_10-1`），而正文例题编号为 `例9-1` ~ `例9-35`（对应 `ex_9-1`）。维护时切勿将 `10-X` 误改为 `9-X`。
2. **《小题300》/《强化240》/《真题分类》**：
   - `labels` 为纯数字字符串 `'1'`, `'2'`, ...，前端自动映射为 3 位补零文件名 `q001_question.png`（无独立 `_solution.png`）。

## 四、图片裁切、遮盖与拼接规范（Image Standards）

> [!IMPORTANT]
> 任何重裁、遮盖或拼接产出的图片，必须满足 **「同章等宽、原位还原、纯白无痕、拼接自然」** 四大视觉标准。

### 4.1 画布宽度一致性与真实水平位置
1. **先测基准宽度 $W$**：
   - 动手裁切前，先用脚本读取同章节下相邻正常图片的像素宽度 $W$（例如：《822教材》恒为 `2005 px`，《夜雨强化》恒为 `1536 px`，《老姚高数》按同节现有图片宽度如 `1476 px` 或 `1800 px` 对齐）。
2. **整栏等比缩放，严禁局部窄框裁切**：
   - 从 PDF 渲染页面（推荐 `dpi=300`）提取时，**横向（X 轴）必须截取与同章节基准图片完全一致的版心左右边界**，再等比缩放到目标宽度 $W$。
   - **严禁做法**：只沿着某一行短公式的文字包围盒（Bounding Box）窄裁，导致图片宽度缩水，或者窄裁后居中贴在白底上导致题号缩进与上下文严重错位。
   - **正确效果**：图片中的题号、正文左边界、公式缩进必须与原书版心位置 100% 吻合。

### 4.2 非相关内容的纯白遮盖（Masking）规范
当一道题与上一题/下一题在同一行或同一段落内，或者需要将大题拆分为独立小问时：
1. **使用纯白矩形（`RGB(255, 255, 255)`）徹底抹除无关内容**。
2. **零残留检查**：
   - 遮盖无关小问时，**必须连同无关小问末尾遗留的逗号（`，`）、分号（`；`）、句号（`。`）、顿号或残留括号一并抹除**！绝不允许出现悬空的标点符号或半截文字笔画。
   - 当保留公共题干 + 第 $(k)$ 小问（如抹除 `(1)(2)` 仅留 `(3)`）时：
     - 若 `(1)(2)` 占用了多行独立高度，应在抹除 `(1)(2)` 后，将「公共题干行」与「第 $(k)$ 小问行」**垂直紧凑拼接**（中间留 `12~18 px` 正常行距），避免图片中间出现一大片无意义的空白断层；
     - 若在同一行内，则将前置小问纯白遮盖，保留真实水平位置，或按同章节统一风格左对齐排版。
3. **剔除混入的栏目头**：
   - 若某道例题恰好位于「补充练习」或下一小节标题上方，裁切该题或解析时，务必将底部混入的「补充练习」字样或下一题题头彻底裁除/纯白遮盖。

### 4.3 跨页或多图垂直拼接（Vertical Splicing）规范
当一道题的题干或解析跨页，或由用户提供多张分图（如 `_1.png`, `_2.png`）需要合成单张图片时：
1. **统一宽度**：若各分图宽度存在微小差异，先以章节标准宽度 $W$ 为基准统一宽度（等比缩放或白底对齐）。
2. **去头去尾**：裁除上一页底部的页码、页脚横线与多余留白；裁除下一页顶部的页眉、书名横线与多余留白。
3. **自然接缝**：将各段图像垂直拼接在纯白画布上，上下两段文字墨迹之间的垂直间距控制在 **`16~24 px`**（与正文标准行距一致），确保视觉上浑然一体，无生硬断层或黑线。

## 五、用户数据迁移与熟练度合并规则（Data Migration）

所有用户刷题数据均保存在 `kaoyan_tiku_data.json` 的 `chapters[chapterId].questions[slug]` 下。

### 5.1 存储键（Slug）生成规则对照表

| 题本类型 | `labels[i]` 示例 | `imgLabels[i]` | 磁盘文件名前缀 | `kaoyan_tiku_data.json` 中的键名 (`slug`) |
| :--- | :--- | :--- | :--- | :--- |
| 常规习题 | `"3-21 (2)"` | 无 | `pb_3-21_(2)` | `"pb_3-21_(2)"` |
| 常规例题 | `"例8-1 (I)"` | 无 | `ex_8-1_(I)` | `"ex_8-1_(I)"` |
| 章末例题（822） | `"例题1"` | 无 | `ce_1` | `"ce_1"` |
| 小题300/240/真题 | `"1"` | 无 | `q001` | `"pb_1"` |
| **老姚高数** | `"12.2-5"` | `"12-13"` | `pb_12-13` | **`"pb_12-13"`**（以 `imgLabels` 为准！） |
| **36讲挂载1000题** | `"1-1"`（伴章） | 无 | `pb_1-1` | **`"q1000::pb_1-1"`** |
| **李范全书挂载习题** | `"1-1"`（伴章） | 无 | `pb_1-1` | **`"lfxiti::pb_1-1"`** |

---

### 5.2 多题合并（$N \to 1$）字段聚合规则

当将 $N$ 道小题（如 `q_1, q_2, ..., q_N`）合并为 1 道大题 `q_merged` 时，严禁直接丢弃旧记录，必须按以下规则聚合各字段：

| 字段名 | 类型 | 合并聚合规则 |
| :--- | :--- | :--- |
| `level` | `string` | • **优先遵循用户显式指令**（例如用户指定「合并后熟练度保留为较熟练」，则设为 `"green"`）。<br>• 若用户未指定，按已做小题的最低/最保守熟练度聚合（优先级：`red` > `orange` > `yellow` > `green` > `gold` > `none`）。<br>• 等级对照：`gold`（登峰造极）、`green`（较熟练/炉火纯青）、`yellow`（一般/略有小成）、`orange`（不熟/初窥门径）、`red`（完全不会/寸步难行）、`none`（未做）。 |
| `mastered` | `boolean` | 严格由合并后的 `level` 派生：`merged.level === 'gold'`。 |
| `wrong` | `boolean` | 严格由合并后的 `level` 派生：`merged.level === 'red' \|\| merged.level === 'orange'`。 |
| `history` | `Array<{ts, level}>` | 将所有被合并小题的 `history` 数组合并，按时间戳 `ts` **升序排列**，并剔除同一毫秒的重复项。若用户指定了新的 `level` 且原 `history` 为空或最新状态不符，可保留完整历史轨迹。 |
| `errorCount` | `number` | 取被合并各小题 `errorCount` 之和（或统计合并后 `history` 中 `red`/`orange` 的次数，取较大值）。 |
| `lastReviewed` | `number \| null` | 取所有被合并小题中最大的 `lastReviewed` 时间戳：$\max(q_i.\text{lastReviewed})$。 |
| `note` | `string` | 收集所有被合并小题中的非空 `note`，去重后使用换行符 `\n` 拼接（如有多条可加原小题号前缀），**绝不丢失任何一条用户笔记**。 |
| `topics` | `Array<string>` | 取所有被合并小题 `topics` 数组的**并集（去重）**：`[...new Set(items.flatMap(q => q.topics || []))]`。 |
| `qbad` / `sbad` | `boolean` | 若本次合并同时重裁并修复了题干/解析图，设为 `false`；否则取逻辑或 `Boolean(q_i.qbad)`。 |

---

### 5.3 单题拆分（$1 \to N$）字段继承规则

当将 1 道大题 `q_orig` 拆分为 $N$ 道独立小问 `q_1, ..., q_N` 时：
1. 若 `q_orig` 已有刷题记录，拆分出的每个子题 `q_k` **默认深拷贝克隆** `q_orig` 的 `level`、`mastered`、`wrong`、`errorCount`、`lastReviewed`、`history`、`note`、`topics`。
2. 克隆完成后，**必须从 `questions` 对象中 `delete questions[origSlug]`**，防止未拆分的旧键成为孤儿数据干扰统计。

---

### 5.4 顺延题号重命名：两阶段防覆盖法（Two-Phase Rename）

> [!WARNING]
> 当因合并或拆分导致后续题号整体平移时（例如 `pb_12-10` 移至 `pb_12-7`，`pb_12-13` 移至 `pb_12-10`），**绝对禁止在同一个对象或目录下直接按顺序循环覆盖重命名**！直接原地重命名极易因遍历顺序不当引发「A 覆盖 B，B 又覆盖 C」的灾难性数据丢失。

**标准两阶段安全重命名法**：
1. **第一阶段（迁入临时命名空间）**：
   - **磁盘文件**：先将所有需要变更的文件移动/复制为带 `__tmp_` 前缀的文件（如 `pb_12-10_question.png` $\to$ `__tmp_pb_12-7_question.png`），或先全部生成到独立的 `temp_out/` 目录中校验无误。
   - **JSON 数据**：先在内存中构建全新的 `newQuestions = {}` 映射表，根据精确的 `oldSlug -> newSlug` 映射表从旧对象读取并写入 `newQuestions[newSlug]`。
2. **第二阶段（原子替换与清理）**：
   - **磁盘文件**：删除旧序号文件，将所有 `__tmp_pb_*` 统一重命名为正式的 `pb_*`。
   - **JSON 数据**：校验 `newQuestions` 的键数量与内容无误后，一次性赋值给 `chapterData.questions = newQuestions`。

## 六、标准作业流程（6 步 SOP）与验收清单

每次执行题目拆分、合并或批量换图时，严格按以下 6 个步骤推进：

### Step 1：盘点与备份（Pre-flight Check）
- [ ] 定位原书 PDF 页码，核对原书题号、小问结构、是否包含「补充练习」或跨页解析。
- [ ] 读取同章节正常图片的像素宽度 $W$，作为本次裁切的目标宽度。
- [ ] 列出完整的题号映射表：`Old Label / Old ImgLabel / Old Slug` $\longleftrightarrow$ `New Label / New ImgLabel / New Slug`。
- [ ] 检查这些题目在 `kaoyan_tiku_data.json` 中是否含有 `level`、`note`、`topics`、`history` 数据。

### Step 2：图片高精度裁切、遮盖与拼接
- [ ] 从原始 PDF 以 `300 DPI` 渲染原页，按版心宽度提取并缩放至基准宽度 $W$（或处理用户提供的替换图）。
- [ ] 执行纯白遮盖（`#FFFFFF`），彻底清除无关题干、无关小问及**残留的逗号/分号/句号/栏目头**。
- [ ] 若涉及跨页或多图合并，执行垂直拼接（段间留白 `16~24 px`）。
- [ ] **调用 `view_file` 逐张目视检查生成的新图片**，确认宽度一致、字迹清晰、无截断、无残影。

### Step 3：磁盘文件与 `js/chapters.js` 路由更新
- [ ] 使用「两阶段安全重命名法」更新 `题库/<子模块>/<ch>/` 下的 `_question.png` 和 `_solution.png`，清理多余的旧图。
- [ ] 更新 `js/chapters.js` 中对应章节的：
  - `total`（总题数）
  - `labels`（显示题号数组）
  - `imgLabels`（仅《老姚高数》必改）
  - `sections`（更新 `start`、`count`、`exampleCount`）
  - `parts`（更新各分区 `start`、`count`）
  - `MATH_KNOWLEDGE_DATA[chId]`（仅 30讲/36讲/1000题/夜雨强化必改：同步 `sections`、`subSections`、`itemDescs`）

### Step 4：`kaoyan_tiku_data.json` 数据平滑迁移
- [ ] 按第 5 节规则合并或拆分题目状态记录，迁移顺延题号的数据键。
- [ ] 若本次替换修复了标为不合格的图片，将对应题目的 `qbad` / `sbad` 置为 `false`（并从 `badQuestions` / `badSolutions` 集合中移除）。

### Step 5：自动化验证脚本（Verification）
执行一键校验脚本及项目测试套件，确保以下断言 100% 通过：
1. **数组长度一致性**：
   - `chapter.labels.length === chapter.total`
   - 若有 `imgLabels`：`chapter.imgLabels.length === chapter.total`
   - 若有 `sections`：`sum(s.count) === chapter.total` 且各节 `start` 首尾相接无断层
   - 若有 `parts`：`sum(p.count) === chapter.total` 且各段 `start` 首尾相接无断层
   - 若有 `MATH_KNOWLEDGE_DATA`：`itemDescs.length === chapter.total`
2. **磁盘文件完整性**：
   - 遍历本章所有题目调用 `getQuestionImagePaths()`，验证磁盘上每一个 `question` 图和 `solution` 图均存在（`fs.existsSync` 为 `true`），且目录内无多余孤儿图片。
3. **单元测试通过**：
   - 运行 `node tests/storage_test.js` 与 `node tests/unit_tests.js`，全部 PASS。

### Step 6：Git 子模块与主仓库双提交（Dual-Repo Commit & Push）
由于 `题库/*` 均为独立 Git 子模块，**必须先提交并推送子模块，再提交并推送主仓库**：

git -C "d:\tj\822\考研题库\题库\<子模块名>" add -A
git -C "d:\tj\822\考研题库\题库\<子模块名>" commit -m "fix(<ch>): 拆分/合并/替换 <题号范围> 题目与解析图片"
